# Spec: Tooling — Prettier Setup

## Goal

Add Prettier to enforce consistent code formatting across the entire codebase, enforced automatically on every commit via a pre-commit hook.

## Scope

**Included:**

- Install and configure Prettier with a `.prettierrc` file
- Install and configure `eslint-config-prettier` to disable ESLint rules that conflict with Prettier
- Install and configure `husky` for Git hooks
- Install and configure `lint-staged` to run Prettier only on staged files before each commit
- Add a `format` script to `package.json`

**Out of scope:**

- Reformatting existing files in bulk (can be done manually with `pnpm format` after setup)
- ESLint rule changes beyond disabling style conflicts via `eslint-config-prettier`
- CI check for formatting (pre-commit hook is the enforcement mechanism)

## Implementation steps

### 1. Install dependencies

```bash
pnpm add -D prettier eslint-config-prettier husky lint-staged
```

### 2. Create `.prettierrc`

```json
{
  "printWidth": 100,
  "tabWidth": 2,
  "useTabs": false,
  "semi": true,
  "singleQuote": false,
  "trailingComma": "all",
  "bracketSpacing": true,
  "arrowParens": "always",
  "endOfLine": "lf"
}
```

### 3. Create `.prettierignore`

```
node_modules
.next
styled-system
pnpm-lock.yaml
```

### 4. Integrate `eslint-config-prettier` into `eslint.config.mjs`

Add `eslint-config-prettier` as the last entry in the ESLint config so it overrides any style rules:

```ts
import eslintConfigPrettier from "eslint-config-prettier";

export default [
  // ...existing config...
  eslintConfigPrettier,
];
```

### 5. Configure `lint-staged` in `package.json`

```json
"lint-staged": {
  "**/*.{ts,tsx,js,mjs,json,md}": "prettier --write"
}
```

### 6. Initialize husky and add pre-commit hook

```bash
pnpm exec husky init
```

Set the content of `.husky/pre-commit`:

```sh
pnpm exec lint-staged
```

### 7. Add `format` script to `package.json`

```json
"format": "prettier --write \"**/*.{ts,tsx,js,mjs,json,md}\""
```

## Edge cases & error states

- `pnpm-lock.yaml` must be in `.prettierignore` — Prettier can corrupt it since it has its own format managed by pnpm.
- `styled-system/` must be in `.prettierignore` — auto-generated by Panda CSS, should never be touched manually.
- `eslint-config-prettier` must be the **last** entry in `eslint.config.mjs` — order matters; earlier entries may re-enable conflicting rules.
- `endOfLine: "lf"` requires that the repo `.gitattributes` (if present) does not force CRLF on checkout — verify or add `* text=auto eol=lf`.
